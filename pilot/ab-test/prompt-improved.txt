How to search (follow this; it reflects where hardening agents usually miss bugs):
- Go breadth-first. First list every public function, class and CLI entry point. Budget your time so every module gets examined, rather than going deep on a few.
- For each API, try degenerate inputs: empty, zero, one element, negative numbers, very large sizes. Check that falsy values (0, "", False, None, empty containers) are not confused with "missing" or "not given".
- If the library parses, serializes or formats anything, round-trip it: dump(parse(s)) == s for documents that were parsed and then edited (insert, replace, delete), and parse(dump(x)) == x. Probe escaping (backslashes, quotes, newlines, unicode), whitespace, comments, ordering and special characters.
- If it implements a format, protocol or standard (file formats, URLs, query languages, dates and times, paths), recall the spec's rules and check both directions: it must reject what the spec forbids and accept everything the spec allows.

- Hostile and unusual values: objects whose __repr__/__str__/__eq__/__hash__ raise, unhashable arguments, subclasses, and generators or iterators that can only be consumed once.
- State: behaviour after copy, deepcopy and pickle; caches and indexes after mutation; use after close.
- Performance: time each operation that could be called on large input at 10x and 100x size; flag anything that grows faster than linearly.
